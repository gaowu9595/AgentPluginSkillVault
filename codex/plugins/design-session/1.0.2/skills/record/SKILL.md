**参数**：`$ARGUMENTS` = `<项目目录> [--propagate]`，如 `OverseaPartner` 或 `OverseaPartner --propagate`。参数为空时搜索工作根目录下所有 `.ai/context.md`。

## record（记录本轮变更/决策）

**目标**：从当前对话中提炼变更点/决策点/消除分歧，登记到变更追踪.md（新增 CHG），更新 context.md，**不立即改设计文档**。

**与其他指令的区别**：

| | record | record --propagate | change "xxx" | save |
|-|--------|--------------------|--------------|------|
| 变更来源 | AI 从对话自动提炼 | AI 从对话自动提炼 | 用户显式指定 | 不关注变更，只做全量保存 |
| 登记 CHG | ✅ | ✅ | ✅ | ❌ |
| 更新 context.md | ✅ | ✅ | ✅ | ✅ |
| 立即改设计文档 | ❌ | ✅（P0） | ✅（P0） | ❌ |
| 触发时机 | 对话中途，随时可用 | 对话中途，想立即传播 | 显式说明变更内容 | 对话结束，宏观总结 |

**典型使用场景**：
- 对话中确认了几个技术细节/方案选型，想先记下来不打断当前节奏
- 消除了分歧（如 GC-05 代码实锤），需要登记结论但不想现在改文档
- 对话结束前快速归档本轮决策

**步骤**：

1. **扫描当前对话**，提炼以下类型的内容：
   - **变更点**：需求细化、设计决策变化、字段/接口调整
   - **决策点**：方案选定、技术选型确认（如"方案C：channel表加crypto_id字段"）
   - **消除分歧**：代码/文档实锤验证的结论（如"GC-05：零改动，代码实锤"）
   - 过滤：背景信息、重复讨论、未定结论、纯工作量估算

   **⚠️ 方案确认副作用检查**（提炼时必执行）：
   对每个"确认/验证"类结论，额外检查是否隐含数据模型或接口变更：
   - 含"某侧加字段"、"调用方适配"、"零改动由 X 侧处理" → 问：加在哪张表？对应详细设计数据模型是否已有该字段？
   - 含"接口由 X 提供/Y 调用" → 问：详细设计的 API 定义/调用链是否已体现？
   - 有隐含变更 → 提炼为独立变更点，不能只记"已确认"结论

2. **输出提炼结果，等用户确认**
   ```
   ## 发现以下变更/决策，确认后登记 CHG：

   1. GC-02~05 确认：环境变量配置/方案C/独立PG/服务注册零改动（代码实锤）
   2. 一客一密调用 mss-gocrypt，不自己实现（方案C）

   确认登记？（y/全部确认，或指定序号）
   ```

3. **用户确认后，登记变更追踪**
   - 新增 CHG-XXX 记录，含影响分析表
   - 所有受影响文件标记为待处理 checkbox（不立即改文件）
   - 处置标记：`⏸️ P0 待处理`（需要改但本次不改）

4. **更新 context.md**
   - 已确认的待确认项 → 移到决策区，标注确认来源
   - 追加讨论纪要（一行摘要 + CHG 编号）
   - **同步刷新编码进展表**：如果本轮变更涉及某个模块/任务的状态变化（如完成、策略调整、阻塞解除），立即更新 context.md 中对应的编码进展表行（状态图标 + 备注），不等 save
   - > **原则**：变更追踪 checkbox 打勾的同时，context.md 编码进展表也要同步——两者始终保持一致，避免 context 耗尽时进展丢失

5. **输出记录摘要**（≤10行）
   ```
   ## 已登记 CHG-XXX

   **新增 CHG**：CHG-038（GC-02~05 确认 + 一客一密方案C）

   **待处理文件**（下次 change --pending 时处理）：
   - [ ] P0 `架构设计/mss-gocrypt-ums基础设施改动确认清单.md`
   - [ ] P0 `详细设计/渠道管理详细设计.md`（一客一密方案C）

   **从待确认移除**：GC-02/03/04/05
   **仍待确认**：GC-01（需肖振国）
   ```

**`--propagate` 参数**：加上后在步骤 3 之后额外执行 P0 文件更新，等同于 `change` 的完整流程。
