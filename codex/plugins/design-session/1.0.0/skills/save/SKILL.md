## save（保存当前状态）

**目标**：将当前对话的新决策、新进展写入持久化文件，保证变更追踪完整。

**步骤**：

### 1. 变更扫描 + 补录（不可跳过）

扫描当前对话，识别变更信号：
- 决策确认（方案选定、技术选型、待确认项已有答案）
- 设计变更（字段/接口/流程调整）
- 消除分歧（代码/文档实锤的结论）

读 `架构设计/变更追踪.md`，对比已有 CHG：
- **有遗漏** → 先补录 CHG（走 record 流程），再继续
- **无遗漏** → 继续

### 2. 增量更新 context.md

读取现有 context.md，分析本轮对话产出：
- 新增的关键决策 → 追加到"关键决策"
- 新增的进展 → 更新"当前进展"
- 新发现的待确认问题 → 追加到待确认索引
- 资料理解状态变化 → 更新状态表

**原则**：增量修改，不覆盖已有内容。

### 3. 落盘讨论纪要 + 归档

**落盘**（有实质性讨论时）：
- 追加到 context.md "讨论纪要"部分
- 格式：`#### YYYY-MM-DD <主题>（CHG-XXX）`
- 篇幅：每次 ≤10 行

**归档**（条数超过 10 条时自动执行）：
- 将最早的纪要原文移动到 `.ai/history.md`，直到剩 5 条
- context.md 留指针：`> 更早的纪要已归档到 history.md（截至 YYYY-MM-DD）`
- history.md 按日期倒序，新归档追加到顶部

### 4. 纠错记忆

回顾本轮对话：用户是否纠正过 AI 的错误？
- 有纠正 → 立即追加到 `<项目>/.ai/corrections.md`
- 跨项目通用的纠正 → 同步写入 `MEMORY.md`
- 格式：`- ❌ <错误行为> → <正确做法> — <简短原因> <!-- added: YYYY-MM-DD -->`

### 5. 附带维护（有需要时顺手做，非必须）

按需执行，不逐项检查：
- **README.md**：本次新增/删除了设计文档 → 更新文档地图；项目阶段变化 → 更新状态快照
- **corrections 清理**：超过 30 天未再犯的条目 → 移到 history.md
- **未落盘摘要**：本次读取了原始资料但没落盘 → 提醒用户

### 6. 自检 + 输出

**自检**（只在发现问题时输出，无问题则跳过）：

| 检查项 | 触发条件 | 输出 |
|--------|---------|------|
| P0 变更未完成 | 变更追踪有未勾选的 P0 | 🚨 醒目警告 |
| P1 变更未完成 | 变更追踪有未勾选的 P1 | ⚠️ 普通提示 |
| 基础设施缺失 | `.ai/context.md` 或 `corrections.md` 或 `README.md` 不存在 | 自动创建 |
| 一致性巡检建议 | 本轮修改 ≥3 个设计文档 **且** 涉及跨模块变更 | 建议执行 `/design-session:check consistency` |

**输出变更摘要**：
```
## Save 完成

**本轮修改的文件**：[列表]
**未完成变更**：[如有]
**纠错记录**：[如有新增]
```
