# 数据库设计审核回归样例

> 仅用于验证 `database-review` Skill。真实审核不得加载本文件，防止把固定答案带入独立 Agent 上下文。

## CASE-01 十三张任务型候选表

**输入特征**：一个月结流程被拆成 task、scan、claim、error、retry 等 13 张表；其中多数表只保存一次任务执行状态。

**必须发现**：表数量超过用户旅程中的持久化业务事实数量；逐表执行删除挑战；默认记为 P1；提出合并、复用现有任务能力或改为运行日志的方案。

**禁止捷径**：不得因“便于扩展”或表名完整而保留；不得只给总表数结论而省略逐表判断。

## CASE-02 重复现有流水

**输入特征**：现有 `credit_change_record/detail` 已保存不可变资金变更历史，候选设计又新增 `monthly_credit_history` 保存同类释放和扣费历史。

**必须发现**：出现重复历史事实源；新表默认删除或降为明确可重建投影；要求说明现有流水无法承载的具体证据。

**禁止捷径**：不得因为新表带有 `monthly` 前缀就认定业务不同；不得让两套流水共同参与余额或审计判断。

## CASE-03 冗余 last 字段

**输入特征**：当前状态表保存 `last_release_request_id`、`last_release_record_id` 和 `last_release_reason`，完整释放历史已存在于唯一流水中。

**必须发现**：`last_*` 只能表示最后一次且复制了历史事实；逐字段证明其独立读取或幂等价值，否则删除；幂等请求号应由每次操作的唯一记录承载。

**禁止捷径**：不得把“排查方便”当作三个字段的充分理由；不得不定义超时、重试和并发覆盖语义。

## CASE-04 资金不变量缺失

**输入特征**：余额、已用和预留均落库，但设计没有恒等式、独立重算方法和对账失败处置。

**必须发现**：没有对账公式至少记为 P1；存在重复扣款、重复释放或多条写入路径时记为 P0；要求停写、告警、修复权限和恢复条件。

**禁止捷径**：不得以事务存在代替对账；不得用应用日志代替业务流水。

## CASE-05 索引与查询不匹配

**输入特征**：高频查询按渠道和账期过滤并按时间排序，却没有相应联合索引；另有一个无人使用的单列状态索引。

**必须发现**：查询到索引以及索引到查询都存在缺口；给出列顺序、选择性、排序和写入成本结论。

**禁止捷径**：不得只建议“增加索引”；不得保留无法关联真实查询的索引。

## CASE-06 字段不可解释

**输入特征**：字段说明只把技术名称翻译成中文，NULL、0、默认值、来源、更新时机和读取方均未说明。

**必须发现**：逐字段证据矩阵不完整，字段覆盖率不能达到 100%，冷读失败并记为 P1。

**禁止捷径**：不得根据字段名猜测业务规则；不得只挑金额或状态字段审查。

## CASE-07 旧通过标记

**输入特征**：设计文档或代码基线已经变化，现有 marker 仍绑定旧设计摘要。

**必须发现**：结果为 `stale`，旧报告只能作为历史参考，不允许进入编码；重新生成证据包并按影响范围重跑 Agent。

**禁止捷径**：不得因改动“看起来只改注释”而跳过摘要验证；不得直接覆盖旧审核产物。

## CASE-08 证据不足

**输入特征**：设计声称复用现有账户能力，但证据包没有相关 DDL、ORM、DAL、Service 或测试位置。

**必须发现**：记录已检查范围和证据缺口，状态为 `blocked`；未找到不等于不存在。

**禁止捷径**：不得编造现有表、字段、约束或接口；不得把设计声明升级为 `CODE-FACT`。

## CASE-09 合理的申请级预留

**输入特征**：渠道 Credit 账户只保存渠道聚合预留，多笔申请需要独立冻结、分月释放和结束；现有不可变流水保存每次资金变化。

**必须发现**：保留申请级当前状态表；解释渠道账户外键和 1:N 基数；区分申请当前状态与历史流水；逐字段质疑 `last_release_*`；要求“账户预留总额 = 所有有效申请 remaining 之和”。

**禁止捷径**：不得因已有资金流水而删除当前业务状态表；不得让申请状态表替代不可变流水；不得把渠道聚合余额误解释为单笔申请状态。

## CASE-10 failed 完整基线后的局部 CHECK 修订

**输入特征**：上一轮 failed，但 11/11 表、112/112 字段、两份原始输出和主裁决均完整；本轮只修复一个 NULL-safe CHECK 和一个函数 manifest，表/字段分母未变。

**必须行为**：选择 delta；继承未变覆盖；只启动数据模型或资金工程中受影响方向；不得重读 112 个字段。

## CASE-11 P2 不触发循环

**输入特征**：P0/P1 已清零，仅发现命名或说明类 P2。

**必须行为**：登记 P2 并结束当前审核；不得自动修文档后重新启动 Agent。

## CASE-12 Agent 402/payment 失败

**输入特征**：Agent 返回 `402 Payment Required` 或明确 quota/payment/auth/permission 错误。

**必须行为**：立即返回 independent_review_unavailable；不得等待、重试、切第三个 Agent 或退回 full。若 complete-baseline 无未解决 P0 且 delta 预检通过，可单独给 conditional coding_readiness。

## CASE-13 事务拓扑变化

**输入特征**：新增资金 writer，改变跨表原子提交集合或统一锁顺序。

**必须行为**：选择 full，数据模型和资金安全双 Agent 全部重跑；旧事务结论不得继承。

## CASE-14 纯解释和格式修订

**输入特征**：只增加通俗示例、修改标题或格式，没有字段、约束、索引、事实源或写入路径变化。

**必须行为**：选择 deterministic-only；只做链接、表格、术语和 hash 变更清单检查，不启动 Agent。
