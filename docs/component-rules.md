# 组件边界与交付约束

## 独立性

Vault 是独立项目。组件的源码、构建、版本、安装、自检和卸载不依赖 SwitchAI。
本机开发时可以从已核对的上游副本导入资源，但发布源码和运行包不能引用开发机的
SwitchAI 路径，也不能从其缓存、数据库或私有配置取数据。

组件负责依赖和实际操作，Claude Code/Codex 适配负责客户端目录和公开配置机制。
SwitchAI 等可选宿主负责管理界面，消费有版本的状态与操作结果，不接管上游内部文件格式。
复杂查看器优先复用上游页面。仅高频、稳定的交互才考虑专门的宿主界面。

同一份安装只设一个管理来源。对非 Vault 管理的现有文件，先识别并拒绝覆盖；
不能为了让界面显示成功而再装一份或启动第二个服务。

## 安装与使用

- 安装和启用分别说明；纯 Skill 没有常驻进程，也不承诺每次对话都会自动调用。
- 优先项目范围；用户范围必须明确客户端配置根目录。安装不改模型、账号或其他能力。
- 安装先验证包内清单与固定依赖哈希。ZIP 的自带清单只检查完整性；跨机器分发还须
  用仓库或可信分发方提供的整个 ZIP 的 SHA256 核对来源。
- 核对当前文件后再修改，使用临时目录和替换步骤；保护用户修改、附加文件和已有配置。
- 升级保留恢复路径，记录数据兼容性。卸载运行能力与删除用户数据必须分开。
- 安装、自检不调用模型，不启用 Hooks，不自动访问业务系统，不默认为所有项目启用。
- 目标机器不执行 npm/pip 下载。声称支持的依赖必须随包提供，或明确列为前置条件。
- 每包说明操作系统、架构、客户端支持范围，以及哪些功能需要额外工具或外部服务。

## 管理接口

首批组件提供命令行管理入口。每次输出一个 JSON 结果到 stdout，操作失败返回非零退出码；
诊断输出不得混入 JSON。结果至少包括 `protocolVersion`、`componentId`、
`componentVersion`、`action`、`ok`、`status` 和 `message`。

接口只描述已实现能力。初版为本地安装的 Skill 提供 `install/status/check/uninstall`；
不虚构通用进程管理、服务发现或远程执行平台。后续增加可选字段可以兼容扩展；
更改字段含义、删除操作或改变成功语义必须提高协议主版本。

## 验证与分发

独立验收至少覆盖：临时客户端目录安装、重复安装、修改冲突拒绝、完整性检查、
真实工具自检、卸载保留用户文件，以及双端适配差异。模型是否发现或选用了 Skill，
真实浏览器效果、内网业务验收必须分别记录；文件存在不能证明这些验证通过。

源码、锁定信息、来源、许可证、构建和检查脚本入 Git。ZIP 和大型二进制放本机发行目录、
GitHub Release 或内网 Nginx；没有实际上传时不得把下载地址标为可用。
