# Design Session 流程持久化

用户已确认采用轻量本地方案，不引入 LangGraph。目标是防止遗漏模板、数据库、安全和内容检查，同时复用未变化的证据。

1. 建立一份流程定义，生成带适用性、返工分支的流程图。
2. 增加本地状态校验器：逐项检查结果、范围、报告和输入指纹；输出下一步与编码就绪结论。
3. 接入 next/write/check 及共享状态规则，保留数据库分级审核和微型设计的范围通过语义。
4. 用临时项目测试遗漏、过期、不适用、局部通过、别名冲突和有效证据复用；独立试用一次。
5. 同步 Vault 双端、实际源插件与 Codex 安装包，记录版本和验证结果。

边界：校验器验证证据记录的完整性与新鲜度，不代替业务判断，不自动运行报告中的命令，不阻止绕开插件直接编辑文件。既有项目先核验并登记已有报告，不因升级强制重审。

基线观察：旧 next 能提示模板缺失、安全过期，但没有统一机械验收命令；旧规则下“无 DB 变更”直接跳过，没有核查不适用依据。现有 _review/_gate 名称不统一。

完成记录：流程图、状态校验器和入口集成已实现。16 项行为回归通过，包含微型模板路由、不适用空原因、目录新增文件以及需求就绪但设计未写的分支。独立试用未发现阻塞问题。初次元数据校验发现旧 next 描述带尖括号、旧 README 缺门禁入口说明，已按当前规则修正；数据库效率、权限门禁和插件格式校验通过。Vault 双端和实际插件源同步，Codex 重新安装为 1.0.4+codex.20260918081703。
