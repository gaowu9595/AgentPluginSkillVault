# 数据库审核通用回归样例

> 仅用于验证 Skill。真实审核不得加载本文件。

## CASE-01 普通局部字段

**输入特征**：现有表新增一个可空展示字段；不参与唯一性、关联、状态转换、核心不变量或跨表事务。

**必须行为**：选择 quick；不写计划、不启动 Agent、不生成完整证据包；检查该字段是否能关联读取或无需持久化。

## CASE-02 冗余派生字段

**输入特征**：候选字段等于同一行两个权威字段的确定性计算结果，没有性能证据或独立生命周期。

**必须行为**：先执行最小化门禁；默认删除或改为查询时计算；不得以方便查询为充分理由。

## CASE-03 重复历史表

**输入特征**：现有 `entity_change_record` 已保存不可变变化历史，候选设计又新增 `feature_change_history` 保存同类历史。

**必须行为**：识别重复事实源；新表默认删除或降为可重建投影；要求现有历史无法承载的代码证据。

## CASE-04 冗余 last 字段

**输入特征**：当前状态表保存多个 `last_*` 字段，完整历史已存在于唯一事件记录中。

**必须行为**：逐字段证明独立读取或恢复价值，否则删除；“方便排查”不是充分理由。

## CASE-05 不变量缺失

**输入特征**：总量和多个组成量同时落库，但没有恒等式、独立重算方法和异常处置。

**必须行为**：至少记为 P1；存在并发重复写或不可逆错误时记为 P0；事务存在不能代替对账。

## CASE-06 索引与查询不匹配

**输入特征**：高频查询按两个条件过滤并按时间排序，却没有对应联合索引；另有无人使用的单列索引。

**必须行为**：查询到索引、索引到查询双向检查；给出列顺序、选择性和写入成本结论。

## CASE-07 字段不可解释

**输入特征**：字段说明只翻译技术名称，未说明来源、读写方、NULL、默认值和生命周期。

**必须行为**：记为 P1；不得根据字段名猜测语义。

## CASE-08 旧通过标记

**输入特征**：输入摘要已变化，正式标记仍绑定旧摘要。

**必须行为**：结果为 stale；根据变化范围选择 quick/delta/full，不得直接沿用或自动 full。

## CASE-09 合理的子对象当前状态

**输入特征**：父对象只保存聚合值；多个子操作各自具有独立当前状态和生命周期；不可变事件记录保存每次变化。

**必须行为**：允许保留子对象当前状态表；解释 1:N 基数，区分当前状态与历史；继续质疑可由历史重建的复制字段。

## CASE-10 失败基线后的局部约束修订

**输入特征**：上轮覆盖链完整但未通过；本轮只修复一个局部 NULL/CHECK，表和字段集合未变。

**必须行为**：选择 quick 或 delta；继承未变化结论；最多启动一个受影响方向 Agent，不得重读全部字段。

## CASE-11 P2 不触发循环

**输入特征**：P0/P1 已清零，仅发现命名或说明类 P2。

**必须行为**：登记后结束，不自动修复并重启审核。

## CASE-12 Agent 权限或额度失败

**输入特征**：独立审核返回权限、鉴权或额度错误。

**必须行为**：立即返回 independent_review_unavailable；不等待、不换第三个 Agent。

## CASE-13 事务拓扑变化

**输入特征**：新增写入方，改变跨表原子提交集合或统一锁顺序。

**必须行为**：返回 needs_full；展示成本并等待用户确认，不能自动开始 full。

## CASE-14 纯解释和格式修订

**输入特征**：只修改标题、示例或排版，没有持久化语义变化。

**必须行为**：选择 deterministic-only；不启动 Agent。

## CASE-15 上层工作流调用

**输入特征**：概要设计工作流发现一项局部持久化变化。

**必须行为**：调用 database-review 自动路由，不得强制 full，不得创建实施计划。
