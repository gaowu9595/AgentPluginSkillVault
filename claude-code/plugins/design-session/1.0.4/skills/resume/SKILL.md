## resume（恢复上下文）— 分层恢复

**目标**：用最少的读取量，恢复到"能正确工作"的状态。

**步骤**：

1. **验证** `<项目>/.ai/context.md` 存在

2. **只读第 1 层**（仅此三个文件）
   - 读 `<项目>/.ai/README.md`（恢复路由器：文档地图、场景指引、模块依赖）
   - 读 `<项目>/.ai/context.md`（全局上下文：决策、进展、待确认项）
   - 读 `<项目>/.ai/corrections.md`（纠错记忆：之前犯过的错误和用户纠正，**防止重蹈覆辙**）
   - **不读其他文件**

3. **验证资料理解状态**
   - 检查 context.md 中的资料理解状态表
   - 有摘要 → 可信赖；无摘要 → 标记"需亲自读取"

4. **输出恢复摘要**（简洁，不超过 20 行）
   ```
   ## 设计上下文已恢复

   **项目**：<名称>
   **当前阶段**：<阶段>

   ### 可继续的方向
   1. <方向 1>
   2. <方向 2>

   ### 关键待确认项
   - <最重要的 2-3 项>

   > 请告诉我接下来要做什么，我会按需加载对应的设计文档。
   ```

   **编码阶段额外提示**（当前阶段为"编码阶段"时自动输出）：

   > **设计文档同步判断规则**（每次改代码后自问）：
   > - 涉及 API 路径/参数/返回字段变化 → 更新概要设计 §3 接口表
   > - 涉及数据库表字段增减/改名 → 更新概要设计 §6 数据模型
   > - 涉及跨模块调用契约/错误码含义 → 更新对应章节
   > - 函数内实现细节/错误处理/代码组织调整 → **只改代码，不动设计文档**

5. **等待用户指令，按需加载**
   - **不要主动读设计文档**
   - 用户说了任务后，参考 README.md 的"恢复指引"和"模块依赖图"，读取**最小必要文件集**
   - 示例：用户说"改渠道数据模型" → 读渠道管理概要设计 §5/§6 → 查依赖图 → 还需读 D365 同步的字段映射部分
   - 用户明确说"回看某轮迭代"时，先读 `.ai/iterations/README.md` 和对应 `<iter-id>/INDEX.md`，不要全量扫历史目录
