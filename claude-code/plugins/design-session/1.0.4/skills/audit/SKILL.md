# audit（变更追踪审计）

**参数**：`$ARGUMENTS` = `<项目目录>`

**REQUIRED BACKGROUND:** Read `shared/design-session-engine.md` for path conventions.

**目标**：回顾当前对话上下文，发现遗漏的变更记录或未完整传播的变更，刷新变更追踪。

**适用场景**：
- 对话进行了一段时间，担心有变更没有记录到变更追踪
- 用自然语言说了"更新系统需求"，但隐含的变更传播（详细设计、context.md 等）没有跟上
- save 之前做一次全面检查

**步骤**：

1. **加载上下文**
   - 读 `<项目>/.ai/context.md`
   - 读 `<项目>/架构设计/变更追踪.md`

2. **回顾对话，提取变更信号**
   扫描当前对话中以下类型的信号：
   - 明确的设计决策（"用方案X"、"改为Y"、"不做Z"）
   - 隐含的变更（"更新系统需求"背后可能还有详细设计、context.md 需要同步）
   - 待确认项的确认结果（"已确认：..."）
   - 资料新增（新 xlsx、新 API 文档）带来的字段/流程变化
   - 用户纠正 AI 的内容（可能意味着文档里有错误描述）

3. **对比变更追踪，找出遗漏**
   - 对话中发生的变更，是否都有对应的 CHG 记录？
   - 已记录的 CHG，影响范围是否完整？（例如只改了系统需求，但详细设计/context.md 没有登记）
   - 已勾选的 checkbox，是否真的改了？（防止误勾）
   - 有没有隐含的跨文件传播被遗漏？

4. **输出审计报告**
   格式：
   ```
   ## 变更追踪审计报告

   ### 已记录且完整
   - CHG-XXX：...

   ### 已记录但传播不完整
   - CHG-XXX：缺少 [文件名] 的 P1 更新

   ### 发现遗漏变更（建议补录）
   - [变更描述]：来源于对话 "[原文摘要]"
     建议：新增 CHG-XXX，影响范围：...

   ### 待确认项变化
   - [待确认项]：对话中已确认/部分确认，建议更新系统需求待确认项

   ### 总结
   - 需要补录 N 条变更
   - 需要补充 N 个 checkbox
   - 建议执行 /design-session save 落盘
   ```

5. **询问用户是否补录**
   - 列出建议补录的变更，逐条询问是否确认
   - 用户确认后，执行对应的变更追踪记录（不自动改文档，只补录 CHG）
   - 如需同时更新文档，走 change 流程
