# 任务清单业务验收用例

版本：1.0，2026-11-13。本文先于回放执行编写，是演示使用的完整业务输入。
这是自建业务样例，不是从 TP 导入的测试单，也不是公司业务验收。

## 业务约定

任务清单用于当次页面会话内登记和核对工作项。打开或刷新页面时清单为空，
不保存到数据库、账号或浏览器存储。任务名称为纯文本；仅去除首尾空白，保留内部空格。
空字符串以及全部由空格、制表符、全角空格等组成的名称均不允许提交。
成功添加后输入框清空、焦点回到输入框；失败显示“请输入任务名称”，清单和统计不变。

新增任务默认未完成。勾选切换为已完成，再次取消勾选恢复未完成。
“全部 / 待完成 / 已完成”仅筛选显示，不删除数据；统计始终表示完整清单。
删除仅移除所选任务。各测试独立打开页面，不依赖其他用例的结果。

## 用例

| 编号 | 目的 | 前置条件与输入 | 操作 | 预期结果 |
| --- | --- | --- | --- | --- |
| TC01 | 添加正常任务并删除 | 新页面；`核对发布清单` | 填入任务名称，点击添加；随后删除该条 | 添加后仅有此条未完成任务；待完成 1、已完成 0；输入清空并聚焦；成功反馈。删除后清单为空，待完成 0 |
| TC02 | 完成、筛选与恢复 | 新页面；依次添加 `核对发布清单`、`确认回滚方案` | 勾选第一条；依次查看已完成、待完成、全部；取消第一条勾选 | 勾选后待完成 1、已完成 1；各筛选只出现相应任务；恢复后两条均未完成，待完成 2、已完成 0 |
| TC03 | 拒绝空名称 | 新页面；空字符串 | 直接点击添加 | 提示“请输入任务名称”；输入标记无效；无任务，统计仍为 0 |
| TC04 | 拒绝全部为空白的名称 | 新页面；分别输入 3 个半角空格、制表符、全角空格与不换行空格组合 | 对每个输入点击添加 | 每次均提示“请输入任务名称”；无任务，待完成与已完成均为 0 |
| TC05 | 去除首尾空白 | 新页面；`  核对  发布清单　`（首尾含空格，内部两空格） | 输入后按 Enter | 保存的文本精确为 `核对  发布清单`；只去掉首尾空白；输入清空 |
| TC06 | 按纯文本显示特殊内容 | 新页面；`<img src=x onerror=alert(1)> & 核对权限` | 添加任务 | 文本逐字保留；任务内没有 img 或 script 元素；没有弹窗；可以正常完成该任务 |
| TC07 | 长名称、窄屏和主题 | 新页面；中文与无空格长字符串组合 | 添加长任务；在 1280×800、390×844 下分别使用浅色、深色；完成再恢复 | 页面无横向溢出；输入、添加按钮、任务文字与完成控件可见并可操作；长名称换行；四种视图截图附于真实报告 |

## 缺陷与回归判定

缺陷版本直接使用输入原文做非空判断并保存；因此 TC04 失败，TC05 失败。
修复版本先调用 `trim()` 再判断并保存。其余业务逻辑不变。
两轮执行同一份 `task-regression.spec.ts`，不按应用模式调整测试、不跳过、不预期失败、
不更新快照、不重试，也不改变断言或预期值。

完整演示必须得到：缺陷轮 **7 总计 / 5 通过 / 2 失败 / 0 跳过**，且失败仅为 TC04、TC05；
修复轮 **7 总计 / 7 通过 / 0 失败 / 0 跳过**。缺陷轮失败必须来自业务断言，
浏览器启动失败、缺少测试或缺少证据均不能替代缺陷复现。

每轮必须有独立的运行证据目录、真实 Playwright JSON 与 HTML 报告，
每个用例有截图、视频、trace。目录、数量、退出码及相同用例文件 SHA256 写入驱动汇总。
这是离线浏览器回归证明，不证明 Claude/Codex 模型选择、MCP 工具调用、TP 或内网系统集成。
